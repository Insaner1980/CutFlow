# CutFlow V1 Implementation Plan

> Historical implementation record, not current work instructions. The implementation under `src/CutFlow` and executable tests under `tests/CutFlow.Tests` take precedence; see `PROJECT.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify a polished, functional, local-only native Windows video editor with the complete CutFlow V1 workflow defined in the approved specification.

**Architecture:** One packaged WinUI 3 application owns UI and Windows media integration; one MSTest project references its testable model, persistence, history, and timeline code. The JSON project model is authoritative, high-frequency pointer behavior stays in focused control code-behind, and a small set of directly constructed services performs storage, media, composition, text rendering, and export work.

**Tech Stack:** C# 14, XAML, .NET 10.0.302 / `net10.0-windows10.0.26100.0`, Windows App SDK 2.3.1, Windows SDK 10.0.26100.0, WinUI 3, Windows Media APIs, System.Text.Json, MSTest.

## Global Constraints

- Use only stable, supported packages; no preview, experimental, or prerelease dependencies.
- Preserve the original CutFlow name and assets; never use CapCut branding or proprietary material.
- Keep one application project and one small test project; do not add a DI container or architectural framework.
- Keep source media at its original absolute path and never delete it during project or asset deletion.
- Keep V1 magnetic and sequential; keep only V1, T1, and A1 visible in this version.
- Keep all serialized times as integer milliseconds and all identifiers as GUIDs.
- Use Windows native media APIs before considering any external codec dependency; do not add FFmpeg in V1.
- Do not initialize Git, commit, push, publish, deploy, or release; the repository is not currently a Git work tree and the user did not authorize those actions.
- Treat the user-supplied specification as approved; do not stop for routine questions.
